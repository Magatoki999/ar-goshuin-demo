1ユーザーが触る部分

フロントエンド このひな形

ARで参拝証キャプチャ後、result-modal 内に「ご縁を結ぶ」セクションを追加。 円建てで金額を選ぶだけ。ウォレット・ブロックチェーンの概念は一切見せない。 決済UIはStripe Elementsで本番実装。

↓

2バックエンドサーバー（要実装）

サーバーサイド

Stripe Webhookで決済完了を受信 → JPYC送金APIを呼び出す。 現時点ではJPYCの直接送金APIは非公開のため、 運営者ウォレットから神社ウォレットへ手動 or バッチ送金する実装が現実的。

// 疑似コード（Node.js / Edge Function） app.post('/webhook/stripe', async (req) => { const event = stripe.webhooks.constructEvent(...) if (event.type === 'payment_intent.succeeded') { const amountJpy = event.data.object.amount // 例: 500 // JPYC送金（1JPY = 1JPYC） await sendJPYC({ to: SHRINE_WALLET_ADDRESS, // 神社ウォレット amount: amountJpy, // JPYCはJPY建て memo: `御朱印AR奉納 ${new Date().toISOString()}` }) // TX IDをDBに保存 → フロントに返す await db.save({ txid, amount, timestamp }) } })
↓

3JPYCオンチェーン記録

Polygon PoS

JPYC（ERC-20）がPolygon上で神社ウォレットに着金。 Polygonscanで誰でも確認可能な透明な奉納記録になる。 神社側はJPYCを円に換金する場合、JPYC公式の換金フローを利用。

// JPYCコントラクト（Polygon） // アドレス: 0x431D5dfF03120AFA4bDf332c61A6e1766eF37BF6 // ethers.js での送金例 const jpyc = new ethers.Contract(JPYC_ADDRESS, ERC20_ABI, signer) await jpyc.transfer(SHRINE_WALLET, ethers.parseUnits(amount.toString(), 18))
↓

4このひな形に差し替えるもの

差し替えポイント

① Stripe の publishable key → 本物のキーに差し替え
② doHounou() 関数 → Stripe Payment Intent APIを呼び出す処理に変更
③ 管理ダッシュボードのデータ → DBから取得するAPIに接続
④ 神社ウォレットアドレス → 実際のアドレスに設定
⑤ sendLog() に 'hounou' イベントを追加 → 既存のGoogleフォームログと統合

⚠️ 現時点の制約

JPYCへの円→JPYC自動変換APIは2026年3月現在、一般公開されていない。
現実的な実装は「Stripeで円受取 → 運営者が定期的にJPYCに換えて神社ウォレットへ送金」。
JPYC社へのAPI連携交渉 or JPYC Payの加盟店登録が揃えばフル自動化が可能。
